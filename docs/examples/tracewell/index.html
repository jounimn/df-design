Instrument once. Trace everything it calls.

One call at start-up. The SDK wraps the clients your service already uses and sends spans over OTLP to your Tracewell, batched, off the request path.

import { trace } from "@tracewell/sdk";

trace.init({
  service: "orders",
  endpoint: "http://tracewell:4318",
  sample: { ratio: 0.2, keepErrors: true, keepSlow: true },
});
// HTTP, gRPC, queues and SQL are wrapped from here on.
from tracewell import trace

trace.init(
    service="orders",
    endpoint="http://tracewell:4318",
    sample=trace.Sample(ratio=0.2, keep_errors=True, keep_slow=True),
)
# requests, httpx, grpc, celery and SQLAlchemy are wrapped from here on.
import "github.com/tracewell/sdk-go/trace"

func main() {
    trace.Init(trace.Config{
        Service:  "orders",
        Endpoint: "http://tracewell:4318",
        Sample:   trace.Sample{Ratio: 0.2, KeepErrors: true, KeepSlow: true},
    })
    defer trace.Shutdown()
}
// net/http, grpc, database/sql and sarama are wrapped from here on.

Your spans never leave your network.

Tracewell is Apache-2.0 and self-hosted: one container or one chart, on the infrastructure you already run. There is nothing on this page to buy.

Docker Compose

One container for the collector and the UI, one for storage. Point the SDK at port 4318 and the first trace is on screen before the second request lands.

$docker compose -f tracewell.yml up -d

Kubernetes

The chart runs the collector as a DaemonSet and the UI behind your ingress, with the SDK endpoint resolved by the cluster DNS.

$helm install tracewell oci://ghcr.io/tracewell/charts/tracewell

Storage is yours to pick: Postgres to start, ClickHouse when the volume asks for it. Both are a line in the config, and traces can be moved between them.

Sampling, retention, overhead, the licence.

The questions that come up in the first issue thread, answered the way the docs answer them.

Does it need OpenTelemetry?

Tracewell speaks OTLP. Anything that already emits OpenTelemetry spans can send them to Tracewell without the SDK; the SDK is there for the services that have nothing yet.

How much overhead does the SDK add?

Spans are built in the process and shipped in batches off the request path. Sampling happens before a span is built, so an unsampled request pays for a header read and nothing else.

How is sampling decided?

Head sampling by ratio per service, plus every trace that errors or crosses its route's p99 is kept whatever the ratio. The slow ones are the ones you came for.

How long are traces kept?

Retention is a setting per project, in days. The storage you chose sets the ceiling: Postgres for a team's volume, ClickHouse for a fleet's.

What does the licence allow?

Apache-2.0: run it, change it, ship it inside your own product. No copyleft, no open-core tier, no feature behind a key.
